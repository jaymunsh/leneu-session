# leneu-session

긴 Claude Code 작업이 `/clear` 를 넘어가도, 인계 문서를 직접 쓰지 않고 그대로 이어지게 합니다.

English: [README.md](README.md)

긴 작업은 컨텍스트 한 창을 넘깁니다. auto-compact를 기다리면 잃을 게 가장 많은 순간에 요약이 일어나고, 인계 문서를 직접 쓰자면 잊지 않고 챙겨야 합니다. 이 플러그인은 작업하는 동안 기록을 대신합니다. 턴마다 기록하고, 일정 간격으로 체크포인트를 저장하고, `/clear` 를 치면 최신 체크포인트를 복원합니다.

```
/leneu-init                        프로젝트마다 한 번
  ... 평소대로 작업 ...              턴과 체크포인트가 자동으로 기록됨
"/clear를 권합니다"                  플러그인은 권하기만 하고, 시점은 직접 정함
/clear
.                                  아무거나 짧게 입력하면 이어서 진행
```

> **상태: 0.1.0, 초기 버전.** 훅, 체크포인트, 복귀 로직은 자체 테스트로 검사했고 실제 `claude -p` 실행으로도 확인했습니다. 대화형 전체 흐름(`/clear` 후 `.`)은 아직 실사용으로 오래 검증하지 못했으니, 이상한 점이 있으면 알려 주세요.

## 설치

```bash
claude plugin marketplace add jaymunsh/leneu-session
claude plugin install leneu-session@leneu-session
```

설치 후 `/reload-plugins` 를 치세요. 명령어와 훅은 이때 로드되고 `/clear` 로는 다시 로드되지 않습니다. 프로젝트마다 설치할 필요 없이 한 번만 설치하면 됩니다. `python3`(3.8 이상)만 있으면 되고 다른 의존성은 없습니다.

나중에 갱신하려면:

```bash
claude plugin marketplace update leneu-session
claude plugin update leneu-session@leneu-session
```

첫 줄은 저장소 clone을, 두 번째 줄은 설치본을 갱신합니다. 둘 다 돌린 뒤 `/reload-plugins` 를 치세요.

설치 없이 시험하려면:

```bash
git clone https://github.com/jaymunsh/leneu-session.git
claude --plugin-dir ./leneu-session
```

**명령은 전체 이름으로 치거나 메뉴에서 고르세요.** `/leneu` 까지 치고 메뉴에서 고르거나, `/leneu-session:leneu-stop` 처럼 전체를 칩니다. `/leneu-stop` 같은 짧은 이름은 시험에서 불안정했고, 한 번은 `Unknown command` 가 나왔습니다. Enter 전에 실행될 명령을 확인하세요. 이 문서는 읽기 쉽도록 짧은 이름으로 적었습니다.

## 흐름 자세히 보기

```
── 세션 1 ─────────────────────────────────────────────
  > /leneu-init                 이 프로젝트에서 켠다

  (작업)                        턴마다 오늘 로그에 추가됨

  컨텍스트가 약 100K 늘 때마다    짧은 턴 하나로 체크포인트를 쓰고
                                "체크포인트 저장"이라고 답함

  창의 30%를 넘기면              그 답에 /clear 권고가 함께 붙음

  > /clear                      적당한 시점에 직접 친다

── 세션 2 ─────────────────────────────────────────────
  (최신 체크포인트와 그 뒤의 턴이
   이미 컨텍스트에 들어와 있음)

  > .                           저장소 상태가 기록과 맞는지 확인한 뒤
                                다음 액션부터 이어서 진행
```

**`/clear` 는 언제 쳐도 됩니다.** 권고는 알림일 뿐입니다. 권고가 뜨기 전이라도 작업 하나가 끝났을 때가 가장 좋은 시점입니다.

**직접 해야 하는 것:** `/clear` 입력과 그 뒤의 메시지 하나입니다. 훅으로는 세션을 지울 수 없고, 새 세션은 입력이 있어야 응답합니다. 이전 작업과 무관한 메시지를 보내면 복원된 기록은 무시합니다.

### 체크포인트에 담기는 것

체크포인트는 무슨 일이 있었는지가 아니라 다음 세션이 움직이는 데 필요한 것을 적습니다. 아래 항목을 쓰되 해당 없는 항목은 빼고, 전체 6000자 이내로 씁니다.

- 현재 작업의 요구와 사용자 정정 (**원문 그대로**)
- 확인된 사실: 경로, 명령, 값, 에러
- 변경 파일과 검증 여부
- 결정: 고른 것, 버린 것, 이유
- 막다른 길: 시도했다 실패한 것과 이유
- 다음 액션: 1~3개, 파일 경로 포함

가장 중요한 것은 막다른 길입니다. 무엇이 바뀌었는지는 `git log` 에도 남지만, 어떤 접근을 포기했는지는 이 기록에만 남습니다.

### 세션 시작 방식별 동작

| 시작 방식 | Claude가 받는 것 |
|---|---|
| `/clear` | 최신 체크포인트나 handoff, 그리고 그 뒤의 턴 |
| 새 세션 | 위와 같고 작성 시각이 함께 전달됨. 24시간이 지났으면 이어갈지 먼저 물어봄 |
| 압축 직후 | 기록 위치만. 압축 요약이 이미 있고 작업이 진행 중이기 때문 |
| 재개, fork | 없음. 대화가 이미 있기 때문 |
| `claude -p` | 없음. 턴은 기록되지만 체크포인트는 요청하지 않음 |

주입되는 내용은 최대 8000자입니다. 체크포인트가 너무 길면, 다음 액션이 끝에 있으므로 앞뒤를 모두 남기고 전체 기록의 위치를 적어 둡니다.

### 지난 작업 물어보기

명령어 없이 말로 하면 됩니다. 함께 들어 있는 스킬이 처리합니다.

- *"지난주에 그 타임아웃 어떻게 고쳤지?"*: 로그를 검색합니다.
- *"이번 주에 뭐 했지?"*: 주제별로 묶어 요약합니다.
- *"이건 남겨줘"*: 훅이 못 잡는 이유나 제약을 직접 기록합니다.
- *"어디까지 했지?"*: 최신 기록을 찾아 저장소와 대조한 뒤 브리핑합니다.

## 명령어

| 명령 | 하는 일 |
|---|---|
| `/leneu-init` | 이 프로젝트에서 켭니다. 꺼 둔 프로젝트는 기록을 유지한 채 다시 켭니다. |
| `/leneu-stop` | 끕니다. 기록은 남습니다. |
| `/leneu-handoff [초점]` | 지금 인계 문서를 쓰고 붙여 넣을 프롬프트를 줍니다. |
| `/leneu-brief [--test]` | 프로젝트 전체를 외부 독자에게 설명하는 문서를 씁니다. |

### `/leneu-handoff`: 수동 인계

체크포인트가 자동이므로, 지금 바로 기록을 남기고 싶거나 다른 에이전트나 다른 컴퓨터처럼 훅이 없는 곳에서 이어갈 때만 쓰면 됩니다. 마지막 출력은 절대경로가 들어간 한 줄입니다.

```
/Users/me/projects/foo/.leneu-session/handoffs/handoff-20261109-1430.md 읽고 검증한 뒤 이어서 진행해줘.
```

인자로 범위를 좁힐 수 있습니다: `/leneu-handoff 인증 리팩터링만`. 새 handoff를 쓰면 체크포인트 간격도 초기화되어 바로 뒤에 체크포인트가 겹치지 않습니다. 켠 적 없는 프로젝트에서 실행하면 폴더는 만들지만 자동 기록은 꺼 둡니다.

### `/leneu-brief`: 프로젝트를 다른 쪽에 설명하기

`/leneu-handoff` 는 *진행 중인 작업*을 넘기고, `/leneu-brief` 는 저장소를 열어본 적 없는 독자에게 *프로젝트 자체*를 설명합니다. 결과는 `.leneu-session/project-brief.md` 입니다.

- **혼자 완결됩니다.** 받는 쪽에 저장소가 없을 수 있어 "README 참고" 같은 포인터에 기대지 않습니다.
- **근거를 표시합니다.** 내용마다 `[실행]`(돌려 봄), `[코드]`(코드를 읽음), `[기록]`(로그나 대화에서 가져옴)을 붙여 추측이 사실처럼 전달되지 않게 합니다.
- **쌓인 기록을 씁니다.** 결정과 막다른 길을 로그와 handoff에서 가져와 저장소로 확인합니다. 이미 뒤집힌 결정은 "예전엔 이랬고 지금은 이렇다"로 적습니다.
- **제자리에서 갱신합니다.** 다시 실행하면 기록된 커밋 이후 바뀐 곳만 읽습니다. 설계 결정과 함정은 저장소로 복구할 수 없으므로 항상 이어받습니다.
- **`--test` 로 빈틈을 찾습니다.** 서브에이전트가 문서만 읽고 돌리는 법과 시작 지점을 답해 보고, 답하지 못한 부분을 채웁니다. 토큰이 더 들어 기본으로는 꺼져 있습니다.

## 설정

필요하면 `.leneu-session/config.json` 을 만드세요. 모든 키는 선택이고, 잘못된 값은 기본값으로 대체됩니다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `context_window` | `1000000` | 컨텍스트 창 크기(토큰). **자동으로 감지할 수 없습니다.** |
| `clear_recommend_pct` | `30` | 창의 이 비율을 넘긴 첫 턴이 끝날 때 `/clear` 를 권하고, 이후 체크포인트마다 다시 권합니다. |
| `checkpoint_every_pct` | `10` | 컨텍스트가 창의 이 비율만큼 늘 때마다 체크포인트를 요청합니다. |

기본값에서는 약 100K 토큰마다 체크포인트를 요청하고, 권고는 300K를 넘긴 첫 턴이 끝날 때 뜹니다. 훅은 턴 사이에만 실행되므로, 한 턴이 길면 기준을 크게 넘긴 뒤에 뜰 수 있습니다.

**200K 창을 쓴다면 바꾸세요.** 그대로 두면 권고가 뜨기 전에 auto-compact가 먼저 일어날 수 있습니다.

```json
{"context_window": 200000, "clear_recommend_pct": 45}
```

### 기본값을 이렇게 정한 이유

체크포인트를 간격마다 쓰는 이유는 문제가 생기기 *전에* 기록이 있어야 하고, 끊긴 세션에는 다음 기회가 없을 수 있기 때문입니다. 실행 중인 세션이 직접 쓰는 이유는 전체 맥락을 이미 알고 있고 프롬프트 캐시로 읽어서, 별도 세션을 띄우는 것보다 입력 비용이 약 10분의 1이기 때문입니다.

## 생기는 파일

필요한 명령을 실행하기 전까지는 아무것도 생기지 않습니다.

```
<프로젝트>/.leneu-session/
├── .gitignore              # 내용은 *. 폴더 전체가 git에서 제외됨
├── logs/YYYY-MM-DD.md      # 턴과 체크포인트. 삽입만 하며 영구 보존
├── handoffs/handoff-*.md   # /leneu-handoff 문서. 최근 10개 유지
├── project-brief.md        # /leneu-brief 문서. 제자리에서 갱신
├── config.json             # 선택
├── hook-errors.log         # 훅 오류. 다음 세션 시작 때 알림
├── hook-errors.old.log     # 이미 알린 오류
├── disabled                # /leneu-stop 상태일 때 존재
├── .state.json             # 세션별 읽은 위치와 토큰 기준값
└── .pending-checkpoint.md  # 로그로 옮겨지기 전 잠시 머무는 체크포인트
```

로그는 이런 모습입니다.

```markdown
## 2026-11-09 14:02 turn
**요청:** add() 버그 고쳐줘
**결과:** 뺄셈을 덧셈으로 고쳤습니다. 테스트 통과.
**변경:** /path/to/calc.py
**도구:** Read, Edit, Bash

## 2026-11-09 14:15 checkpoint tokens=147000 session=6f74a221
**원본:** /path/to/transcript.jsonl
### 다음 액션
1. ...
```

로그는 일자별로 나뉘고 다시 쓰이지 않습니다. 턴마다 요청은 400자까지, 결과는 결론이 있는 끝쪽 600자를 남깁니다. 더 필요하면 `**원본:**` 줄이 가리키는 전체 transcript를 보면 됩니다.

## 동작 원리

Python 스크립트 하나와 훅 네 개입니다.

| 훅 | 발동 시점 | 하는 일 |
|---|---|---|
| `Stop` | 턴이 끝날 때 | 새 턴을 기록하고, 완성된 체크포인트를 로그로 옮기고, 때가 되면 새 체크포인트를 요청 |
| `SessionStart` | 세션이 시작될 때 | 끊긴 세션이 남긴 체크포인트를 복구하고, 위 표의 내용을 주입하고, 훅 오류를 알리고, 새 git worktree를 켬 |
| `PreToolUse` (`Write`) | 파일을 쓰기 전 | 플러그인의 체크포인트와 handoff 파일만 자동 승인 |
| `PreCompact` | 압축 직전 | 압축 전 transcript 위치를 적어 둠 |

알아 두면 좋은 설계 결정입니다.

- **컨텍스트 크기는 transcript에서 읽습니다.** 훅은 컨텍스트 비율을 전달받지 못하므로, 마지막 메인 응답의 `input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens` 를 더합니다. 서브에이전트 사용량은 제외하고, 값이 줄면 압축으로 봅니다.
- **체크포인트 지시는 `decision: block` 이 아니라 `additionalContext` 로 보냅니다.** block은 transcript에 훅 오류로 저장되고, 모델이 그 "오류"를 체크포인트에 적는 일이 있었습니다.
- **두 단계로 로그 형식을 지킵니다.** Claude는 임시 파일에 쓰고, 훅이 로그로 옮길 때 헤더와 시각을 붙입니다. 본문의 `#`, `##` 헤더는 낮춰서 새 로그 절처럼 보이지 않게 합니다.
- **훅은 작업을 막지 않습니다.** 모든 실패를 잡아 기록하고 나중에 알리며, 스크립트는 항상 exit 0으로 끝납니다. `/clear` 복원 실패는 바로 알립니다.
- **transcript가 깨져 있어도 기록은 멈추지 않습니다.** 어느 단계가 실패해도 읽은 위치를 저장하므로 같은 턴이 반복해서 기록되지 않습니다.
- **읽은 위치를 모르면 마지막 턴만 기록합니다.** 상태 파일 손상, 세션 중간에 켜기, fork가 여기 해당합니다. 로그는 고칠 수 없으므로 중복되거나 원치 않는 턴이 남는 것보다 한 턴 빠지는 쪽이 낫습니다.
- **transcript를 잠깐 기다립니다.** `Stop` 시점에 마지막 응답이 아직 디스크에 없을 수 있어 최대 2초 기다립니다. 기다리지 않으면 토큰 수가 한 턴 밀리고 결과가 비어서 기록됩니다.
- **git worktree는 알아서 처리합니다.** 폴더가 git에서 제외되어 새 worktree에는 없습니다. 메인 체크아웃에서 켜져 있으면 새 worktree에 폴더를 만들고 설정을 복사합니다. 로그는 worktree끼리 공유하지 않습니다.
- **프로젝트는 작업 폴더에서 위로 올라가며 찾고,** 가장 가까운 `.git` 이나 홈 폴더에서 멈춥니다.

## 안전과 개인정보

- **기본은 꺼짐입니다.** `/leneu-init` 을 실행하기 전에는 기록하지 않습니다. 하위 폴더 전체에 적용되는 홈 폴더에서는 실행을 거부합니다.
- **로컬에 머뭅니다.** 플러그인 자체는 아무것도 외부로 보내지 않습니다. 다만 복원된 기록은 컨텍스트로 Claude 대화에 들어갑니다.
- **git에서 제외됩니다.** 폴더 안에 자체 `.gitignore` 가 있습니다. 로그에는 프롬프트와 결과가 인용될 수 있으니, 공유할 의도가 아니라면 그대로 두세요.
- **자동 승인 범위가 좁습니다.** `.pending-checkpoint.md` 와 `handoffs/` 바로 아래의 `handoff-*.md` 만 승인합니다. 경로를 먼저 확인하므로 심볼릭 링크로 다른 곳을 가리킬 수 없습니다. 사용자의 deny, ask 규칙은 그대로 적용됩니다.
- **비밀값 가림에는 한계가 있습니다.** 훅이 쓰는 기록에서 `sk-…`, `ghp_…`, `github_pat_…`, `AKIA…`, `Bearer …`, `xoxb-`/`xoxp-…` 같은 흔한 형식을 가립니다. 형식 없이 붙여 넣은 비밀번호는 가리지 못합니다. 수동 handoff는 비밀값을 쓰지 말라는 지시에 의존합니다.
- **커밋된 `.leneu-session/` 은 플러그인을 켭니다.** 폴더 존재 자체가 스위치라서, 이 폴더를 커밋한 저장소에서는 플러그인이 켜지고 내용이 `CLAUDE.md` 처럼 주입됩니다.
- **설정을 건드리지 않습니다.** 훅은 플러그인 안에 들어 있고 `settings.json` 은 바꾸지 않습니다.

## 알려진 한계

- **`/clear` 는 수동입니다.** 훅으로 실행할 수 없습니다.
- **복귀에 입력이 한 번 필요합니다.** 새 세션은 입력을 기다리므로 `.` 같은 짧은 메시지가 필요합니다.
- **체크포인트는 화면에 보이고 토큰이 듭니다.** 짧은 턴이 하나씩 추가됩니다. 너무 잦으면 `checkpoint_every_pct` 를 조정하세요.
- **동시 세션을 구분하지 않습니다.** 같은 폴더를 터미널 여러 개로 열면 `/clear` 가 다른 터미널의 체크포인트를 읽을 수 있습니다. 복귀 때 저장소를 확인하므로 위험은 줄어듭니다. 서브에이전트와 worktree는 영향이 없습니다.
- **`context_window` 는 직접 설정합니다.** 훅 입력에 포함되지 않습니다.
- **비대화형 판별은 문서화되지 않은 값에 의존합니다.** `claude -p` 에서 `CLAUDE_CODE_ENTRYPOINT` 는 `sdk-cli` 입니다. 값이 없으면 대화형으로 취급합니다.
- **중단 직후 `/clear` 하면 그 턴이 빠집니다.** Esc 후에는 `Stop` 이 발동하지 않아, 바로 `/clear` 하면 중단된 턴이 로그에 남지 않습니다.
- **다른 에이전트는 아직 지원하지 않습니다.** Claude Code가 우선이고 Codex 등은 추후 고려합니다. `/leneu-handoff` 결과는 일반 파일이라 어느 에이전트나 읽을 수 있습니다.

## jay-session에서 옮겨 오는 경우

leneu-session은 [jay-session](https://github.com/jaymunsh/jay-claude)을 잇습니다.

| | jay-session | leneu-session |
|---|---|---|
| 인계 | `/jay-new` 수동 | 체크포인트 자동, 원할 때 `/leneu-handoff` |
| `/clear` 후 | 경로를 주입하고 Claude가 파일을 읽음 | 기록과 이후 턴을 직접 주입 |
| `/clear` 시점 | 직접 판단 | 설정 가능한 기준에서 권고 |
| 로그 | 월별 `devlog.md` | 일자별 파일, 항상 복귀에 사용 |
| 위치 | `.claude/session/` | `.leneu-session/` |

옮길 때 jay-session을 비활성화하세요. 둘 다 켜면 훅이 겹칩니다. 기존 `.claude/session/` 파일은 옮기지 않고 그대로 남습니다.

```bash
claude plugin disable jay-session@jay-claude
```

## 끄기

```
/leneu-stop                 이 프로젝트의 기록을 멈추고 기존 기록은 유지
/leneu-init                 다시 켜기
```

꺼 둔 동안의 턴은 다시 켠 뒤에도 기록되지 않습니다. 프로젝트의 기록을 모두 지우려면 `.leneu-session/` 폴더를 삭제하세요. 플러그인을 제거하려면:

```bash
claude plugin uninstall leneu-session@leneu-session
```

훅과 명령어가 제거되고, 프로젝트에 이미 쓰인 파일은 그대로 남습니다.

python3 scripts/session_hook.py --selftest
