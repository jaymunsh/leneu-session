# leneu-session 설계

작성 2026-11-09. 표기: **[사용자]** 사용자가 정한 것, **[판단]** 설계자가 정했고 사용자가 뒤집을 수 있는 것.

## 왜 만드는가

jay-session은 컨텍스트가 40% 언저리에 오면 사람이 직접 판단해 `/jay-new`를 치고, `/clear`를 치고, 복귀 프롬프트를 붙여넣어야 한다. leneu-session은 이 흐름에서 사람의 일을 **`/clear` 한 번과 복귀 시 `.` 같은 짧은 입력 한 번**으로 줄인다. 이 입력은 사용자가 수용했다. [사용자] jay-session의 전반적인 내용을 승계하는 후속작이다. [사용자]

`/clear`만 수동으로 남는 이유는 공식 훅 문서에 훅이 슬래시 커맨드를 실행하거나 대화를 초기화하는 수단이 없기 때문이다. auto-compact로 입력을 0으로 만드는 안과 터미널에 키 입력을 흘려 넣는 안은 검토 후 버렸다. [사용자]

## 목표

- 일정 작업량마다 체크포인트가 자동으로 일자별 파일에 쌓인다.
- 컨텍스트가 커지면 `/clear`를 권하는 안내가 자동으로 뜬다.
- `/clear` 후 최신 체크포인트가 자동으로 주입되어 하던 일을 잇는다. 사용자는 하던 일을 잇는 경우가 더 많다고 했다. [사용자]
- `/jay-brief`를 개선한 `/leneu-brief`를 제공한다. 개선 내용은 설계자에게 맡겨졌다. [사용자]

## 비목표

- Codex 등 다른 에이전트 지원. 이번 범위는 Claude Code뿐이다. 다만 추후 활용을 염두에 둔다. [사용자] 지금 할 일은 저장 폴더 이름에서 `.claude`를 빼는 것까지다. 어댑터 계층을 미리 만들지 않는다. [판단]
- 비용 절감을 성과 지표로 삼지 않는다. 근거 논문의 절감 배수는 추정 가격 모델 기반이고, 정가로는 압축 쪽이 더 비싼 사례도 있다. [판단]
- 기존 `.claude/session/` 기록의 이전.

## 안티골 (동작해도 실패로 보는 경우)

- 작업 도중에 끊긴다. 체크포인트는 턴 경계에서만 일어나야 한다.
- 체크포인트 지시가 무한 반복되거나 턴마다 뜬다.
- 복귀 후 다음 세션이 "무엇을 하고 있었는지" 사용자에게 다시 묻는다.
- `/leneu-init`을 하지 않은 프로젝트에 파일이 생긴다.
- 훅 오류가 사용자의 작업을 막는다. 훅은 실패해도 작업을 막지 않고 `.leneu-session/hook-errors.log`에 남긴다. 다음 세션 시작 때 새 오류가 있으면 한 줄로 알린다. 고장을 모른 채 `/clear`하면 맥락을 잃기 때문이다. [판단]

## 제약

- Python 3 표준 라이브러리만 사용한다. jay-session의 `session_hook.py`를 출발점으로 삼는다. [판단]
- 훅 입력에는 컨텍스트 %와 창 크기가 없다(statusline에만 있고, 그 자리는 claude-hud가 쓰고 있다). 토큰 수는 transcript의 마지막 메인 assistant 항목 `message.usage`에서 `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`로 계산한다. 2026-11-09 실제 transcript로 필드 존재를 확인했다.
- 훅 타임아웃 안에 끝나야 하며, 매 턴 실행되므로 무거운 작업을 하지 않는다.

## 구성

Claude Code 플러그인 `leneu-session`. [사용자]

```
.claude-plugin/plugin.json
hooks/hooks.json
scripts/session_hook.py        # 훅 진입점 + --selftest
commands/leneu-init.md
commands/leneu-handoff.md
commands/leneu-brief.md
skills/session-manager/SKILL.md  # 복귀·로그 검색·수동 기록의 자연어 진입점
```

명령어 파일명에 `leneu-`를 붙이는 이유: `init.md`로 하면 짧게 친 `/init`이 내장 명령과 겹친다. `leneu-init.md`면 `/leneu-init`으로 칠 수 있다. [사용자]

## 저장 구조

```
<프로젝트 루트>/.leneu-session/
├── .gitignore            # 내용은 `*` 한 줄. 프로젝트 .gitignore를 건드리지 않는다
├── config.json           # 선택. 없으면 기본값
├── logs/YYYY-MM-DD.md    # 삽입만 함. 절대 수정·삭제하지 않음
├── handoffs/handoff-YYYYMMDD-HHMM.md  # 수동 인계 문서. 최근 10개 유지
├── project-brief.md      # 하나만 유지
└── .state.json           # 세션별 커서와 토큰 상태
```

- 켜기 스위치는 `.leneu-session/` 폴더의 존재이고, 끄기 스위치는 그 안의 `disabled` 파일이다. 폴더가 없거나 `disabled`가 있으면 모든 훅이 즉시 종료한다. [사용자: `/leneu-init`으로 시작, `/leneu-stop`으로 끔] 폴더를 지우는 방식으로 끄면 로그까지 사라지므로 표시 파일을 쓴다. [판단]
- 훅은 `cwd`에서 위로 올라가며 `.leneu-session/`을 찾고, 가장 가까운 `.git`(폴더 또는 파일)이 있는 위치에서 멈춘다. git 밖이면 홈 디렉터리에서 멈춘다. jay-session은 `cwd`만 봐서 하위 폴더에서 실행되면 놓치고, 멈춤 조건이 없으면 상위 폴더의 설정이 무관한 저장소에 번진다. [판단]
- **worktree:** SessionStart 시점에 현재 위치가 worktree이고(`.git`이 파일) 자체 `.leneu-session/`이 없는데 메인 체크아웃이 켜져 있으면, 그 worktree에 자동으로 생성한다. 메인 체크아웃 경로는 `.git` 파일과 `commondir`을 읽어 구한다. 로그는 worktree별로 분리한다. [판단, 사용자가 위임]
- **동시 세션:** 폴더당 대화형 세션 하나를 가정한다. 사용자는 같은 폴더를 동시에 여는 일이 드물고 병렬은 주로 서브에이전트라고 했다. [사용자] 서브에이전트는 `Stop` 대신 `SubagentStop`을 쓰고 transcript의 sidechain은 제외하므로 영향이 없다. 드물게 동시에 열면 `/clear`가 다른 터미널의 체크포인트를 읽을 수 있으며, 이 한계를 README에 적고 복귀 시 현재 상태 확인으로 완화한다. 세션 연결 장치와 파일 잠금은 만들지 않는다. `.state.json`은 임시 파일에 쓴 뒤 교체해 깨지지 않게 한다. [판단]
- 일자별 파일 하나에 턴 기록과 자동 체크포인트를 함께 쓴다. [사용자: 분량마다 삽입하는 형태 승인] 수동 handoff만 별도 파일로 둔다. 복귀 프롬프트에 넣을 고정 경로가 필요하기 때문이다. [사용자]
- 로그는 영구 보존한다. 로그에는 프롬프트와 응답 일부가 들어가므로 자동 `.gitignore`로 커밋을 막는다. [판단]

### 로그 형식

```markdown
## 2026-11-09 14:02 turn
**요청:** ...(400자로 자름)
**결과:** ...(600자로 자름)
**변경:** a.py, b.py
**도구:** Edit, Bash

## 2026-11-09 14:15 checkpoint tokens=147000 session=6f74a221
**원본:** /path/to/transcript.jsonl
### 현재 작업의 요구와 사용자 정정 (원문)
### 확인된 사실 (경로·명령·값·에러)
### 변경 파일과 검증 여부
### 결정 (고른 것, 버린 것, 이유)
### 막다른 길
### 다음 액션 (1~3개, 파일 경로 포함)
```

체크포인트 항목은 논문 Appendix A의 3요소와 G.1 프롬프트, jay-session의 "함정" 절을 합친 것이다. [판단] **현재 작업의 요구와 이후 사용자가 준 정정·제약은 요약하지 않고 원문을 유지**하며, 복귀 후 새 체크포인트에도 이어 적는다. 새 작업으로 넘어가면 이전 작업의 요구는 빼서 불어나지 않게 한다. [판단] `**원본:**`의 transcript 경로는 훅이 넣는다. 잘린 출력과 전체 대화를 다음 세션이 grep으로 찾기 위한 포인터이며, 가이드의 "로그 외장화"를 별도 장치 없이 구현한 것이다. [판단] 각 체크포인트는 그것만 읽어도 이어갈 수 있어야 한다. 줄거리를 쓰지 않는다.

복귀 시 찾는 방법은 최신 일자 파일부터 거슬러 올라가며 마지막 `^## .* checkpoint ` 헤더를 찾고, 다음 `## ` 헤더 전까지 잘라내는 것이다. 체크포인트 본문은 `##` 헤더를 쓰지 않는다.

## 훅 동작

### Stop

1. `.leneu-session/`이 없으면 종료.
2. `stop_hook_active`가 거짓이면 커서 이후의 **모든** 턴을 `turn` 항목으로 append한다(LLM 없음, 토큰 0). 커서는 `.state.json`에 세션별로 저장한다. jay-session의 `parse_turn`은 커서 이후의 마지막 요청 하나만 기록해, Stop이 돌지 않은 중단 턴을 잃는다. 이 동작은 승계하지 않는다. `task-notification`, Stop 훅 피드백 같은 시스템 메시지는 사용자 요청으로 기록하지 않는다. 흔한 비밀값 패턴(API 키, 토큰)은 기록 전에 마스킹한다. [판단]
3. 현재 토큰 수를 계산한다. 세션 상태에 다음을 둔다.
   - `baseline`: 세션의 첫 측정값. 이번 세션 기준 약 47K로, 작업 전 고정 비용이다.
   - `last_ckpt`: 마지막 체크포인트 지시 시점의 토큰 수. 초기값은 `baseline`.
4. 토큰 수가 `last_ckpt`보다 작으면(압축이 일어났다) `baseline`과 `last_ckpt`를 현재 값으로 재설정한다.
5. `.leneu-session/.pending-checkpoint.md`가 있으면 훅이 `checkpoint` 헤더(시각, 토큰, 세션)를 붙여 일자별 로그에 append하고 임시 파일을 지운다.6. `stop_hook_active`가 참이면 여기서 끝낸다. 무한 반복을 막는다.
7. `현재 − last_ckpt ≥ context_window × checkpoint_every_pct / 100`이면 `last_ckpt`를 갱신한 뒤 `{"decision":"block","reason":...}`를 출력한다. `reason`은 형식을 주고 모델에게 임시 파일 작성만 시킨다. 다른 작업을 시작하지 말라고 명시한다. 작성이 거부되거나 실패하면 다음 간격에 다시 시도하며 턴마다 재촉하지 않는다.
8. 현재 토큰이 `context_window × clear_recommend_pct / 100` 이상이면 `reason`에 "작성 후 마지막 줄에 `/clear`를 권한다"를 덧붙인다. 지시 자체가 체크포인트 간격에 묶이므로 턴마다 반복되지 않는다.

모델이 로그를 직접 쓰지 않는 이유: append-only가 규칙이 아니라 구조로 보장되고, 시각을 짐작할 일이 없으며, 쓰기 권한을 임시 파일 하나로 좁혀 자동 승인할 수 있다. [판단]

### PreToolUse

`Write`의 `file_path`가 해당 프로젝트의 `.leneu-session/.pending-checkpoint.md`와 정확히 일치하거나, 경로를 정규화했을 때 `.leneu-session/handoffs/` 바로 아래의 `handoff-*.md`일 때만 허용한다. 그 외에는 아무 판단도 내리지 않는다. 기본 권한 모드에서도 프롬프트 없이 체크포인트가 돌아가게 하기 위함이다. [판단]

### 비대화형 실행

`claude -p` 같은 비대화형 실행에서는 체크포인트 지시와 본문 주입을 하지 않는다. 사람이 없는 실행을 멈추거나 작업에서 벗어나게 하면 안 된다. [판단]

**시점 결정 [판단, 사용자가 위임]:** 턴 경계에서만 일어나므로 작업을 끊지 않고 프롬프트 캐시가 살아 있어 가장 저렴하다. 간격을 시작 토큰이 아니라 실제 증가분으로 재므로 플러그인 구성에 따라 시작 토큰이 달라져도 흔들리지 않는다.

체크포인트 작성 주체는 세션의 현재 모델이다. 별도 저가 모델로 돌리지 않는다. 같은 컨텍스트를 새 세션이 다시 읽는 비용이 캐시 읽기의 약 10배이고(Opus 4.5 정가 $5 대 $0.50/M), 시도와 실패의 맥락은 대화 안의 모델만 안다. [판단]

### PreCompact

jay-session과 같다. 압축 시점과 원본 transcript 경로를 로그에 남긴다.

### SessionStart

| source | 동작 |
|---|---|
| `clear` | 최신 체크포인트와 그 이후 `turn` 기록을 주입. "저장소 상태로 다음 액션이 아직 유효한지 확인한 뒤 이어가되, 사용자의 요청이 무관하면 무시하라" |
| `startup` | 같은 내용과 작성 시점을 주입. 24시간 이상 지났으면 이어갈지 먼저 확인하게 함 |
| `compact` | 경로만 전달. 브리핑이나 재질문 금지 |
| `resume`, `fork` | 주입하지 않음 |

`clear`와 `startup`의 본문 주입은 사용자가 요청한 "대화가 0인 상태면 최근 파일을 읽는다"의 구현이다. [사용자] `startup`까지 포함한 것은 설계자의 해석이다. [판단] `CLAUDE.md` 규칙 대신 훅을 쓰는 이유는 `source`로 상황을 정확히 구분할 수 있고 프로젝트 파일을 건드리지 않기 때문이다. 체크포인트 이후 턴 기록까지 넣는 이유는 체크포인트 뒤의 작업을 다음 세션이 반복하거나 이미 끝난 액션을 다시 하지 않게 하기 위함이다. 체크포인트가 없는 짧은 세션도 턴 기록으로 이어갈 수 있다. [판단] 주입 본문은 8,000자로 자르되 체크포인트를 우선 보존하고, 전체 경로를 함께 넘긴다. 체크포인트와 턴 기록이 모두 없으면 아무것도 출력하지 않는다.

수동 handoff가 최신 체크포인트보다 새로우면 체크포인트 대신 handoff를 주입하고, 그 이후의 턴 기록을 함께 넣는다. handoff의 시각은 파일의 수정 시각을 쓴다. [판단]

## 설정

`.leneu-session/config.json`. 없으면 기본값. 값이 깨졌으면 기본값으로 동작한다. [사용자: 조정 가능하게]

| 키 | 기본값 | 근거 |
|---|---|---|
| `context_window` | 1000000 | 사용자가 1M 기준으로 쓴다고 했다. 훅 입력과 transcript에 창 크기가 없어 설정값으로 둔다. 200K 창이면 프로젝트별로 바꾼다 |
| `clear_recommend_pct` | 30 | 1M에서 300K. 사용자의 30~50% 범위 안에서 설계자가 추천한 값이며 근거 데이터는 없다. 200K 창이면 40~50%를 쓴다 [판단] |
| `checkpoint_every_pct` | 10 | 1M에서 100K마다, 200K에서 20K마다. 시작값이며 쓰면서 조정 [판단] |

1M 기준으로 시작 토큰이 약 47K이면 체크포인트는 약 147K, 247K, 347K에서 생기고, `/clear` 권고는 300K를 넘긴 첫 체크포인트인 347K에서 뜬다. 이후 권고를 무시하고 계속하면 체크포인트 간격마다 다시 권한다. 30%는 논문의 수치가 아니다. 논문이 시험한 16K~48K는 Claude Code에서 쓸 수 없다. 첫 응답 시점에 이미 약 47K를 쓴다.

## 명령어

- **`/leneu-init`:** `.leneu-session/`, `logs/`, `.gitignore`를 만든다. 이미 있으면 상태만 보고한다. `disabled`가 있으면 지워 다시 켠다. 묻지 않는다. 훅은 다음 턴부터 기록한다고 알린다.
- **`/leneu-stop`:** `disabled` 파일을 만들어 끈다. 로그와 handoff는 지우지 않는다. 다시 켜려면 `/leneu-init`. 완전히 지우려면 폴더를 직접 삭제하라고 안내한다. [사용자] 꺼진 체크아웃은 새 worktree에 자동으로 켜지 않는다.
- **`/leneu-handoff [초점]`:** jay-session의 `/jay-new`를 승계한다. [사용자] 체크포인트와 같은 항목으로 `.leneu-session/handoffs/handoff-YYYYMMDD-HHMM.md`를 쓴다. 파일명 시각은 `date`로 얻는다. 인자가 있으면 다음 액션 1번으로 놓는다. 폴더가 없으면 만든다. 최근 10개만 남기고, 지운 것이 있으면 한 줄로 알린다. 체크포인트 간격 계산에도 반영하도록 `last_ckpt`를 현재 토큰 수로 갱신해 직후에 자동 체크포인트가 겹치지 않게 한다. 마지막 출력은 이어갈 프롬프트 한 덩어리다. `.leneu-session/handoffs/handoff-20261109-1430.md 읽고 검증한 뒤 이어서 진행해줘.` `/clear`는 사람이 치므로 대신 실행을 제안하지 않는다.
- **`/leneu-brief`:** 아래.

jay-session에서 이어받는 규칙: 먼저 쓰고 정말 모르는 것만 묻는다, 시각은 `date`로 얻는다, git 저장소가 아니면 git 단계를 뺀다, 로그 과거 항목은 고치지 않는다.

## /leneu-brief

`/jay-brief`의 틀을 유지한다: `.leneu-session/project-brief.md` 하나, 혼자 완결, 얕은 절부터, 설계 결정과 함정은 이어받기, 절대경로 복붙 프롬프트 출력. 사용자가 jay-brief를 실사용해 본 적이 적어 개선은 설계자의 판단이다. [판단]

1. **기준 커밋 표시.** 헤더에 작성 시점 SHA를 적는다. git이 아니면 뺀다.
2. **근거 구분.** 실행 명령과 사실에 `확인됨(실행)` 또는 `추정(코드 읽음)`을 표시한다.
3. **증분 갱신.** 재실행 시 기준 커밋 이후 `git diff --stat`으로 범위를 좁혀 읽는다.
4. **로그 활용.** 체크포인트의 `### 결정`, `### 막다른 길`을 재료로 삼되, 현재 저장소로 유효성을 확인한다.
5. **백지 테스트(옵션).** `/leneu-brief --test`일 때만 서브에이전트가 문서만 읽고 실행법과 수정 지점을 답하게 해 빈틈을 채운다. 토큰이 들어 기본값은 끈다.

## jay-session과의 공존

같이 켜 두면 훅이 중복 실행되므로 설치 시 jay-session을 비활성화한다. 안내는 README에 적는다. 기존 기록은 옮기지 않는다. [판단]

## 구현 순서

가장 불확실한 것은 코드가 아니라 체감이다. 먼저 Stop 체크포인트와 `/clear` 복귀 흐름만 만들어, 임계치를 낮춘 임시 프로젝트에서 사용자가 직접 써 보게 한다. 턴 끝에 끼어드는 것이 거슬리면 나머지를 만들기 전에 시점을 조정한다. [판단]

## 검증 기준

- `session_hook.py --selftest`: 토큰 계산, 턴 append와 커서, 간격 판단, `stop_hook_active` 처리, 압축 후 재설정, 체크포인트 찾기, source별 주입, `.leneu-session/` 없을 때 무동작, 상위 폴더 탐색과 `.git`에서의 멈춤, 임시 체크포인트의 로그 이동, worktree 자동 생성, handoff와 체크포인트 중 최신 선택, 자동 승인 경로의 경계(`..` 포함 경로 거부), 커서 이후 여러 턴 기록, 시스템 메시지 제외, 비밀값 마스킹, 오류 기록과 다음 세션 알림.
- 실제 Claude Code에서 끝까지: 임시 프로젝트에서 `/leneu-init` → 작업으로 체크포인트 발생 확인(`checkpoint_every`를 낮춰 테스트) → `/clear` → 본문 주입과 이어가기 확인.

## 확인 결과 (2026-11-09)

- **Stop:** `{"decision":"block","reason":...}`로 계속 진행시킨다. 8회 연속 제한은 있으나 도구 호출로 초기화되고 체크포인트는 1회라 해당 없다. 문서상 `decision: block`은 transcript에 오류로 보일 수 있어, 표시 방식은 체감 검증에서 확인한다.
- **PreToolUse:** `hookSpecificOutput.permissionDecision: "allow"`. 사용자의 deny/ask 규칙은 그대로 적용된다.
- **SessionStart 자동 시작:** `initialUserMessage`는 `-p` 모드용으로만 문서화되어 있다. `.` 입력으로 간다.
- **비대화형 구분:** 문서에 없다. 실측으로 `claude -p`는 `CLAUDE_CODE_ENTRYPOINT=sdk-cli`, 대화형은 `cli`다. 값이 없으면 대화형으로 취급한다.

## 구현 전에 확인할 것 (작성 당시 메모)

- Stop의 `decision`, `reason`, `stop_hook_active` 정확한 형식과, 8회 연속 제한의 동작.
- SessionStart가 사용자 입력 없이 Claude를 먼저 시작하게 할 수 있는지. 없어도 사용자가 `.` 입력을 수용했으므로 설계는 그대로이며, `.`만 입력해도 주입된 작업을 이어가도록 안내 문구를 쓴다.
- PreToolUse 허용 응답의 형식과, 플러그인 훅의 허용이 사용자 권한 규칙과 어떻게 합쳐지는지.
- 비대화형 실행을 구분할 신호. transcript의 `entrypoint` 필드가 후보이며, 훅 입력만으로 판단이 안 되면 다른 방법을 찾는다.
- 논문 G.1 프롬프트 전문. 받은 요약은 일부 미검증이다. 체크포인트 항목을 다듬는 데만 쓰며, 위 항목 구성을 뒤집는 경우에만 사용자에게 알린다.
