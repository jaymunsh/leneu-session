인계 문서 경로 (첫 줄이 경로다. 시각을 직접 짐작하지 않는다):

!`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/session_hook.py" --handoff-path`

위 경로에 지금까지의 작업을 인계 문서로 쓴다. 새 세션의 나는 이 대화를 전혀 모른다. 파일 경로, 함수명, 명령을 그대로 적는다. "그 함수", "아까 그 파일"은 다음 세션에서 의미가 없다.

- **먼저 다 쓰고, 나중에 묻는다.** 대화에서 추론할 수 있는 것을 전부 채운 뒤 정말 모르는 것만 한 번에 확인한다. 확인할 게 없으면 묻지 않는다.
- git 저장소면 `git status --short` 와 `git log --oneline -5` 를 확인한다. 커밋 안 된 변경이 있으면 그게 인계의 핵심이다. git 저장소가 아니면 git 항목을 뺀다.
- 줄거리를 쓰지 않는다. 다음 세션이 바로 움직이는 데 필요한 것만 쓴다. 비밀값은 적지 않는다.
- 해당 없는 항목은 뺀다.

```markdown
# Handoff — {한 줄 요약}

### 현재 작업의 요구와 사용자 정정 (원문)
{요약하지 말고 원문 그대로. 중간에 사용자가 준 정정과 제약도 포함}

### 확인된 사실 (경로·명령·값·에러)

### 변경 파일과 검증 여부
{git 저장소면 브랜치와 커밋 안 된 변경. 안 돌려봤으면 "미검증"이라고 적는다}

### 결정 (고른 것, 버린 것, 이유)

### 막다른 길 (시도했다 실패한 것과 이유)
{이 문서의 진짜 값어치다. 무엇을 했는지는 git에도 남지만 실패한 시도는 여기에만 남는다}

### 완료 기준 (무엇이 되면 끝인가)
{"테스트 통과"가 아니라 "`pytest tests/auth` 통과하고 로그아웃 후 토큰 거부 확인"처럼 확인할 수 있게}

### 다음 액션 (1~3개, 파일 경로 포함)
{"리팩터링 계속"이 아니라 "src/auth.py:42 의 토큰 만료 처리 추가"처럼}
```

$ARGUMENTS 가 있으면 그게 다음 세션의 주제다. 다음 액션의 1번으로 놓는다. 다른 맥락을 버리라는 뜻은 아니다. 지금까지의 작업과 무관하면 짚고 넘어간다.

마지막 출력은 **복사해서 쓸 프롬프트 한 덩어리뿐**이다. 실제 경로를 넣고, 그 외의 설명이나 요약은 붙이지 않는다. 경로 출력에 "오래된 handoff N개를 지웠습니다"가 있었으면 그 한 줄만 위에 덧붙인다.

```
<인계 문서 경로> 읽고 검증한 뒤 이어서 진행해줘.
```

`/clear` 는 대화를 버리는 동작이라 사람이 직접 친다. 대신 실행하겠다고 제안하지 않는다.
