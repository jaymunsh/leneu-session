브리프 경로 (하위 폴더에서 실행해도 프로젝트 루트를 가리킨다. 경로 대신 안내문이 나왔으면 그 안내문만 전하고 멈춘다):

!`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/session_hook.py" --brief-path`

이 프로젝트가 **무엇이고 어떻게 생겼는지**를 파일 하나로 정리한다. 받는 쪽은 다른 프로젝트에서 일하는 에이전트다. 이 저장소를 열어본 적도, 이 대화를 본 적도 없다.

`/leneu-handoff` 와 혼동하지 않는다. 그건 *하던 작업*을 다음 세션에 넘기는 문서고, 이건 *프로젝트 자체*를 밖으로 설명하는 문서다. 진행 중인 작업은 여기서 맨 마지막 한 절이다.

**혼자 완결돼야 한다.** `README 참고` 같은 포인터는 받는 쪽에서 열 수 없는 주소다. `README.md`, `CLAUDE.md`, `AGENTS.md` 는 재료로 읽되 내용은 이 파일에 추려 담는다.

## 절차

**0. 파일이 이미 있으면 먼저 읽는다.** 위 경로에 파일이 있으면 갱신이다. 헤더의 `기준 커밋` 을 찾아 둔다.

**1. 저장소를 읽는다.** 대화보다 저장소가 먼저다.

```bash
git rev-parse --short HEAD 2>/dev/null   # 실패하면 git 저장소가 아니다
git status --short
git branch --show-current
```

- **새로 쓸 때:** `git ls-files`, `git log --oneline -20`, `git log --stat -5`.
- **갱신일 때:** `git diff --stat <기준 커밋>..HEAD` 와 `git log --oneline <기준 커밋>..HEAD` 로 범위를 좁혀, 바뀐 곳만 다시 읽는다. 기준 커밋을 찾을 수 없으면(rebase 등) 새로 쓸 때처럼 읽는다.
- **git 저장소가 아니면:** 구조는 아래로 대신하고 "최근 흐름" 절과 `기준 커밋` 을 뺀다.

```bash
find . -maxdepth 3 \( -name '.?*' -o -name node_modules -o -name dist -o -name build -o -name target -o -name __pycache__ \) -prune -o -print
```

그리고 `README.md`, `CLAUDE.md` / `AGENTS.md`, 패키지 매니페스트를 읽는다.

**2. 쌓아둔 기록을 읽는다.** "설계 결정"과 "함정" 절의 재료다. 대화에서만 가져오면, 그 결정을 겪지 않은 세션이 쓸 때 문서가 얇아진다.

위 경로가 있는 폴더(`<폴더>`)의 기록을 본다.

```bash
grep -rh -A6 -E '^### (결정|막다른 길)' <폴더>/logs <폴더>/handoffs 2>/dev/null | tail -200
```

없으면 조용히 넘어간다. 그대로 옮기지 않는다. 로그는 그 시점의 기록이니 지금도 맞는지 저장소로 확인한다. **이미 뒤집힌 결정은 "예전엔 이랬고 지금은 이렇다"로 적는다.**

**3. 문서를 쓴다** → 위 경로. 폴더는 이미 준비되어 있다. 시각은 `date "+%Y-%m-%d %H:%M"` 으로 얻는다.

```markdown
# <프로젝트명> — 프로젝트 브리프

생성 2026-11-09
최종 갱신 2026-11-09 20:11
기준 커밋 abc1234 (미커밋 변경 있음)

근거 표시: [실행] 직접 돌려 확인함 / [코드] 코드를 읽고 판단함 / [기록] 로그나 대화에서 가져옴

## 한 줄 요약

## 무엇을 하는 프로젝트인가
왜 존재하는지까지. 무엇을 하는지만 적으면 받는 쪽이 판단을 못 한다.

## 구조
주요 폴더와 핵심 파일. 전체 트리를 붙이지 말고 들어갈 지점을 짚어준다.

## 돌리는 법
설치, 실행, 테스트. 각 명령에 근거를 붙인다. 이번에 돌려본 것만 [실행]이다.

## 아키텍처와 설계 결정
왜 이 구조인지, 무엇을 버렸는지, 어디를 건드리면 무너지는지.

## 함정 / 알아둘 것
시도했다 안 된 것, 헷갈리기 쉬운 것.

## 최근 흐름
커밋 나열이 아니라 "최근 어느 방향으로 움직였나".

## 지금 진행 중인 것
짧게.
```

**근거를 구분한다.** 추측이 사실처럼 전달되는 것이 이 문서의 가장 나쁜 실패다. 돌려볼 수 있고 부작용이 없는 명령은 돌려서 `[실행]` 으로 만든다. 설치, 배포, 데이터를 바꾸는 명령은 돌리지 않고 `[코드]` 로 둔다.

**절 순서는 얕은 것부터다.** 받는 쪽이 위에서부터 읽다가 충분해지면 멈출 수 있어야 한다. 해당 없는 절은 뺀다. 빈 절을 남기는 게 제일 나쁘다.

**다시 실행할 때 통째로 덮어쓰지 않는다.**

| 절 | 처리 |
|---|---|
| 구조 / 최근 흐름 / 지금 진행 중인 것 | 바뀐 범위를 반영해 새로 쓴다 |
| 한 줄 요약 / 무엇을 하는 프로젝트인가 / 돌리는 법 | 실제로 바뀐 것만 고친다 |
| **아키텍처와 설계 결정 / 함정** | **이어받고 덧붙인다. 절대 날리지 않는다** |

저장소로 복구할 수 없는 부분이라서다. 기존 항목이 틀렸으면 지우지 말고 왜 더 이상 맞지 않는지 한 줄 붙인다. `생성` 은 그대로 두고 `최종 갱신` 과 `기준 커밋` 만 바꾼다.

**4. 백지 테스트 (`$ARGUMENTS` 에 `--test` 가 있을 때만).** 토큰이 들기 때문에 기본으로 돌리지 않는다. 서브에이전트에게 이 문서의 절대경로만 주고, 저장소의 다른 파일을 읽지 말고 문서만으로 "어떻게 돌리는가", "기능을 고치려면 어디부터 보는가", "건드리면 안 되는 곳은 어디인가"에 답하고 문서만으로 답할 수 없는 것을 나열하게 한다. 그 빈틈을 저장소에서 확인해 문서에 채운다.

**5. 마무리 출력.** `pwd` 로 경로를 확인해 절대경로를 박은 복붙 프롬프트를 준다. 받는 쪽은 작업 폴더가 다르다. 새로 만든 건지 갱신한 건지 한 줄로 알리고, 갱신이면 무엇이 바뀌었는지도 한 줄 적는다.

```
/Users/me/projects/foo/.leneu-session/project-brief.md 읽고 이 프로젝트 파악해줘.
```
